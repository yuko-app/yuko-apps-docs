Order limits apply to the cart as a whole, regardless of which products are
in it — total item count, total value, or total weight. Use them for rules
like "minimum order value $50", "no more than 20 items per order", or
weight-based shipping constraints.

## Limit conditions

Pick a **condition type**:

- **Limit by total items in the order (Cart Quantity)** — set a minimum
  and/or maximum item count for the whole cart
- **Limit by total value of the order (Cart Value)** — set a minimum and/or
  maximum cart value
- **Limit by total weight in the order (Cart Weight)** — set a minimum
  and/or maximum cart weight, in **lb**, **oz**, **kg**, or **g**

The minimum field is required for every condition type — set it to `1` (or
a value that every order meets) if you only want to enforce a maximum.

<Note>
  Whether "value" includes shipping and taxes is controlled by the
  **Order Value Calculation** setting — see
  [General settings](/order-limits/settings/general).
</Note>

### Multi-currency stores

For **Cart Value** conditions, you can add a row per currency — each with
its own **Currency**, minimum, and maximum. Customers are checked against
the row matching their cart's currency, so a €45 minimum and a $50 minimum
can coexist cleanly.

## Sell in multiples

Enable **Sell products in multiples** to require the quantity to be a
multiple of a value (at least 2). Choose what the multiple applies to with
**Apply multiple to**:

- **Order** — the total cart quantity must be a multiple
- **Each product** — each product's quantity must be a multiple
- **Each variant** — each variant's quantity must be a multiple

## Exclusions

By default an order limit counts the entire cart. Enable **Exclusions** to
leave certain items out of the count, choosing what to exclude:

- **Specific product** — selected products or variants don't count toward
  the limit
- **Specific collection** — products from selected collections don't count

Excluded items can still be purchased — they're simply ignored when the
cart is checked against the rule.

## Use cases & examples

<AccordionGroup>
  <Accordion title="Minimum order value of $50" icon="dollar-sign" description="A cart-wide value floor, with a live “add X more” message.">
    Condition **Cart Value** → **Minimum value in order** `50`. A helpful
    message pattern uses the live remaining amount:

    ```text
    Add {{remaining_total_value}} {{currency}} more to reach our {{minimum_total_product_value}} {{currency}} minimum.
    ```
  </Accordion>
  <Accordion title="No more than 20 items per order" icon="basket-shopping" description="Keep orders within packing and fulfillment constraints.">
    Condition **Cart Quantity** → **Minimum** `1`, **Maximum** `20`.
    Useful for keeping orders within packing or fulfillment constraints.
  </Accordion>
  <Accordion title="Keep orders under a shipping weight cap" icon="weight-hanging" description="A maximum cart weight in your preferred unit.">
    Condition **Cart Weight** → set the maximum and pick the unit (e.g.
    `20` **kg**). The `{{maximum_product_weight}}` and `{{weight_unit}}`
    variables let the message show the exact cap.
  </Accordion>
  <Accordion title="Different minimums for USD and EUR customers" icon="euro-sign" description="Per-currency minimums for multi-currency stores.">
    Condition **Cart Value** → add one row per currency: USD min `50`, EUR
    min `45`. Each customer is checked against their own currency's row.
  </Accordion>
  <Accordion title="A $100 minimum that ignores gift cards" icon="gift" description="A value minimum with excluded products left out of the count.">
    Set the Cart Value minimum, then enable **Exclusions** → **Specific
    product** → select your gift card products so they don't count toward
    the $100.
  </Accordion>
</AccordionGroup>

## Troubleshooting

<AccordionGroup>
  <Accordion title="The value limit uses the wrong total">
    Check **Order Value Calculation** in
    [General settings](/order-limits/settings/general) — *Without shipping
    & taxes* compares the subtotal, *With shipping & taxes* compares the
    order total. If your $50 minimum seems to pass at $47 of products,
    shipping is probably being counted.
  </Accordion>
  <Accordion title="Multi-currency minimum isn't applying">
    Make sure there's a row for the customer's currency — a cart in a
    currency with no matching row isn't checked against your value rule.
    Each row needs its currency selected, or the form reports "Please
    select a currency for this row".
  </Accordion>
  <Accordion title="Weight limits don't trigger">
    Weight rules rely on product weights from your Shopify catalog —
    products with no weight set contribute 0. Check the affected products'
    shipping settings, and confirm the limit's unit matches what you had
    in mind (200 **g** is very different from 200 **oz**).
  </Accordion>
  <Accordion title="Customers bypass the minimum with Buy it now">
    Express checkout buttons skip the cart. Enable **Hide express checkout
    if limits are not met** on the Limits page, and consider **Hide
    payment methods if limits are not met** in
    [General settings](/order-limits/settings/general) as checkout-level
    backstops.
  </Accordion>
  <Accordion title="The message shows, but checkout isn't blocked">
    Open the limit — if an **Enable Checkout Rule** button appears at the
    top, the **Yuko Order Limit** checkout validation is missing. Click it
    to add the validation in Shopify's checkout settings
    (**Settings → Checkout**), and check that
    [Rule settings](/order-limits/settings/general) is set to block.
  </Accordion>
</AccordionGroup>

## Refine the rule

Order limits support
[customer tag and country targeting](/order-limits/limits/targeting),
[scheduling](/order-limits/limits/scheduling), and
[custom messages](/order-limits/customization/messages-translations).
Useful message variables include `{{remaining_total_value}}` (how much more
the customer needs to add to reach the minimum) and `{{weight_unit}}` — see
the [message variables reference](/order-limits/customization/message-variables).
